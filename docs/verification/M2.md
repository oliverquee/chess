## Data invariants

- Exactly two target rows are created together or neither is created.
- A new target leaves one row `in_progress` and the other `queued`.
- Invalid/skipped lifecycle transitions fail explicitly.
- Completion changes the game header and inserts sequential plies in one transaction.
- A dependency failure before session construction does not claim that play started.
- Existing games migrated from the pre-status schema become `completed`, not fabricated queue/progress states.

## Known limitations

- The in-memory `PracticeSession` object itself is not reconstructed after a process crash. Durable SQLite state accurately records `queued` or `in_progress`; resume/recovery UX belongs to the Electron milestone.
- Classification and the final `completed → analyzed` content pipeline belong to M3. M2 exposes and validates the transition boundary only.
